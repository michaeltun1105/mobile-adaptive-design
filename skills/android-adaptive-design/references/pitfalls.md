# Known pitfalls (Figma Plugin API + M3 kit)

### Known pitfalls
- Load every font from the original (`getStyledTextSegments(["fontName"])` + `loadFontAsync`) before resizing text frames; load Roboto for kit components.
- After `resize()` on an auto-layout frame the primary axis becomes FIXED — reset to AUTO where it should hug.
- Don't blanket-set children to FILL when widening a cloned block; only full-width children become FILL. Buttons stay fixed/hug.
- Fixed-width texts in cloned blocks overflow — set to FILL inside a parent with a max width.
- Cloned FILL frames can collapse to 1 high — set `layoutSizingVertical = "HUG"`.
- Images with `scaleMode: FILL` re-crop on resize; check the subject.
- Status bar / gesture bar components are 412 wide — set them to FILL width.
- Dark mode: copy the original's `explicitVariableModes` and set the kit's color collection to Dark.
- Screenshots only after the write returns; never in parallel with edits. `await node.screenshot()` inside `use_figma` returns the image inline (use it when `get_screenshot` URLs can't be downloaded).
- **Target page colour mode:** the target page may default to another mode (e.g. Dark) than the source page. Read `explicitVariableModes` on the source page and the target page; set the same modes on every new screen frame with `setExplicitVariableModeForCollection` (e.g. the team's semantic colour collection → Light, a typography collection → Android), or cloned cards render dark.
- **Cloning from another page:** `await sourcePage.loadAsync()` before `getNodeByIdAsync` + `clone()`; append the clone to the target frame, then set `layoutSizingHorizontal = 'FILL'`.
- **Cloned blocks that were FILL-height** (e.g. a header) collapse to 1 px in a scroll column — set `layoutSizingVertical = 'HUG'` on every direct child of scroll containers after cloning.
- **Charts (non-auto-layout "Chart Area" frames):** don't set them to FILL — keep FIXED and `resize(container.width − 32, h)` with child constraints: lines STRETCH, area/line vectors SCALE, Y labels MIN, X labels STRETCH + `SPACE_BETWEEN`. Divider vectors in the chart container: FIXED, width = container − 32, container `counterAxisAlignItems = 'CENTER'`.
- **App bar without a leading icon** (list pane, detail pane in list-detail): hiding `Leading icon` makes `SPACE_BETWEEN` centre the trailing icon — set the instance `primaryAxisAlignItems = 'MAX'`. The Small configuration keeps its title absolute at x 56; for a pane title flush with the content use `Configuration = Medium`, hide `Leading & Trailing icons`, and set `Text content` padding left/right 0.
- **Hinge alignment with the 96-wide rail:** frame centre is x 452 on 905; place the spacer across it (e.g. left pane x 120–440, spacer 440–464, right pane 464–881), so the left pane is FIXED 320 and the right pane FILL.
- **Mirrored app bar title:** the Small app bar's `Text content` is absolute with a STRETCH constraint; if the instance is FILL inside a parent that is still narrow (e.g. a pane frame created at 100 wide and resized later), the title gets a negative width and renders mirrored (`relativeTransform[0][0] = -1`). Give every pane its final width before inserting app bars, and don't call `setProperties` for booleans that are already at their default. If it happens, delete the instance and insert a fresh one into the laid-out parent.
- **Overlays in auto-layout screens:** a dialog, side sheet, menu or scrim inserted into the screen's auto-layout root joins the flow for a moment, squeezes the panes and mirrors app-bar titles. Create it, set `layoutPositioning = 'ABSOLUTE'` before anything else, then position it. Afterwards search the section for `relativeTransform[0][0] < 0`; a mirrored node inside an instance can't be fixed directly — replace that instance with a clone from a healthy sibling screen (same child-index path).
- **Kit slots:** Basic dialog (`Content` slot), Side Sheet (`Content`), Menu (`List 1 content`) and Toolbar accept children: `slot.appendChild(frame)` then set `layoutSizingHorizontal = 'FILL'`. Side sheet: `Headline text#3022:9`, `Show actions#3022:0`, nested `Close affordance` (icon swap), `Primary button` / `Secondary button`; inset it under the status bar with `paddingTop = 52`, `paddingBottom = 24`. Menu item: hide trailing, swap `Leading element` icon, label via the nested `Content` instance's `Label text`. Kit surfaces are baseline purple — theme them with the brand scheme first (see the design-system-setup skill); only when no theme exists, set dialog/sheet/menu fills to the screen's surface and selected chips / tonal buttons to the brand tint.
- System bars as `layoutPositioning = 'ABSOLUTE'` children of the screen (status bar top, gesture bar bottom, constraints STRETCH), body padding top 52 / bottom 24.
- **Brand-coloured rail / nav bar:** on each instance find nav items with `Selected = True`; bind the `Icon container` fill to the theme's `Schemes/Secondary Container` (or the system's light brand tint variable), and the icon vectors and `Label text` to `Schemes/On Secondary Container` / the system's brand text variable. Look the variables up by name in the saved system — never paste a variable id or hex from another product. Unselected items stay neutral.
- **Destructive dialog action:** bind the Basic dialog's Primary button label fill to the theme's `Schemes/Error` (or the team's destructive variable if the system maps one).
- **Team toolbars in dialogs:** replace the cloned iOS toolbar (glass X / Save) with a wrapper frame (no auto layout, final width, 64 high): App bar `Configuration=Small`, trailing actions off, fills [], `Leading icon` → `close` (`64f805a63adf73d8a9f453e3c4ad5a5ce0d8850a`), headline = title; plus `Button - text` (`c94bd76a8dbf75d7885f3015ad8474d898fca25b`, `Type=Round, Size=Small`, `Show icon#58650:102` false, `Label text#58650:0`) at the right (constraint MAX), label bound to the system's primary/brand variable. At Medium+ prefer a Basic dialog with Cancel/Save at the bottom.
