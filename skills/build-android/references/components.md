If the saved system has `<Product>/M3/…` text styles, use those instead of the kit styles; if the team has its own type scale and chose to keep it, use its heaviest/larger style instead — never swap fonts without the system or the person saying so. **Titles are emphasized by default** (unless the saved system says otherwise): app-bar / pane titles, dialog headlines and side-sheet headlines use the `…-emphasized` style of the same size (Roboto Medium) — headline/medium → headline/medium-emphasized (28), title/large → title/large-emphasized (22), headline/small → headline/small-emphasized (24). Apply with `await text.setTextStyleIdAsync(style.id)` after loading the style's font; it works on text inside kit instances.

Use `importComponentSetByKeyAsync` for "set", `importComponentByKeyAsync` for "component". If an import still fails, re-find it with `search_design_system` scoped to the library key above and report the new key. Buttons, FAB, cards, chips, lists, tabs, text fields: find with `search_design_system` in the kit and record the keys in the report.

**Icon policy (applies when the saved system says `icons.source = 'material-symbols'`; if the team chose to keep their icons, keep them and only replace SF Symbol glyphs that render blank): all icons come from Material Symbols (Google Fonts, https://fonts.google.com/icons), style Outlined, weight from the saved system (default **600** — 400/500 look too light at 20–24dp); selected/active states (rail, nav bar, toggles) use the filled variant (`<name>-fill.svg`).** Pick the symbol whose meaning matches — never an approximate stand-in. Kit icon components may be used only when they are the same Material Symbol (they are named after it); otherwise create it locally. Navigation icons: pick per destination by meaning (outlined unselected, `-fill` selected, selected coloured with the system's brand/primary variable) and record the mapping in the saved system so later screens reuse it. The kit's icon set is small (no route/map/timeline/speed/filter/garage icons), so most product icons come in this way: `npm pack @material-symbols/svg-600` in the workspace (npm is reachable; the Google Fonts site is not), take `outlined/<name>.svg` (viewBox `0 -960 960 960`; set width/height 24), `figma.createNodeFromSvg`, move its vector into a 24×24 local component named after the symbol (constraints SCALE, description "Material Symbols Outlined (wght 600) · <name>"), keep all such components in one frame `_Icons · Material Symbols (…)` above the Section, then `swapComponent` (or set the icon-button `Icon#…` property to the component id) and re-apply the old vector fills (local icons have hard-coded fills, so recolor them: unselected = previous fill, selected = brand). Kit icon components are weight 400 and can't change weight, so swap every visible kit icon instance (also those nested in app bars, menus, chips, icon buttons) to the local 600 component of the same name and re-apply its fills; to change the weight of an existing local icon, set its vector's `vectorPaths` (and x/y) from a freshly imported SVG so instance colour overrides survive. Record every created icon (name → component id) in the saved system's icon frame; reuse those components instead of creating duplicates.

**No hard-coded values.** Every colour is bound to a variable (the saved theme or the team's semantic variables), every text uses a text style (the saved `<Product>/M3/…` styles or the team's), every icon is an instance of a component in the icon frame, and spacing uses the 8dp scale. Never paste raw hex, font names or variable/component ids from another product or from this skill's examples — look them up by name in the current file's saved system (`getSharedPluginData('android_adaptive','system')`) or ask. Raw values are allowed only for guides/annotations (fold guide, section labels) and third-party logos/photos. The contrast audit also lists unbound fills/text so they can be fixed.

Keep M3 instances linked; never hand-draw a bar, rail, button or sheet. Clone the team's own content from the original so their styles and variables stay linked. No device frame (bezel).
